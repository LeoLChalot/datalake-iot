1 · L'idée en une minute

Prendre des photos régulières des stations de vélos

Dans une ville avec des vélos en libre-service (Vélib' à Paris, Vélo'v à Lyon…), chaque station a un certain nombre de vélos garés et de places vides. Ces chiffres changent sans arrêt : quelqu'un prend un vélo, quelqu'un en ramène un.

Le sujet nous demande de répondre à des questions comme « quelles stations sont souvent vides ? » ou « à quelle heure les gens roulent le plus ? ». Pour ça, il faut un historique. Or Internet ne nous donne que l'état actuel.

La solution : un petit programme qui, toutes les 2 min 30, « prend une photo » de toutes les stations et la range dans un placard. Au bout d'une journée, on a 576 photos par ville, et on peut voir comment les choses évoluent.

C'est ça qu'on appelle un flux streaming : des données qui arrivent en continu, petit à petit, au lieu d'un gros fichier qu'on télécharge une seule fois (ça, c'était la partie 1 avec la météo).
2 · Les acteurs

Cinq outils, cinq équivalents de la vie réelle

API CityBikes Le guichet d'information

Un site web fait pour les programmes, pas pour les humains. On lui pose une question (« donne-moi les stations de Paris ») et il répond avec une liste de chiffres. C'est gratuit et il n'y a pas besoin de compte.

citybikes-collector.py Le livreur qui fait sa tournée

Notre script Python. Il va au guichet pour chaque ville, garde seulement ce qui nous intéresse, puis va déposer le résultat au placard. Ensuite il attend 150 s et recommence.

MinIO Un Google Drive installé chez nous

Un logiciel qui stocke des fichiers, comme Google Drive ou Dropbox, mais qui tourne sur ton propre ordinateur. Il range les fichiers dans des « buckets » (des grands dossiers). On l'appelle notre Data Lake : le lac où on déverse toutes les données brutes.

Docker Des boîtes prêtes à l'emploi

Au lieu d'installer MinIO, PostgreSQL et Metabase à la main, Docker les lance chacun dans une « boîte » (un conteneur) déjà configurée. Une commande, et tout démarre.

curl Le coursier

Un petit outil en ligne de commande qui envoie ou récupère quelque chose sur une adresse web. Notre script l'utilise pour déposer chaque fichier dans MinIO.

    6 · À toi de jouer
    
Le lancer pour de vrai, en 4 étapes

    
0 / 4 étapes faites

  

  
    
    
  1. 
      
      
    
        
    Démarrer les boîtes Docker
    
        
    À taper dans un terminal, dans le dossier datalake-iot. Ça démarre MinIO, PostgreSQL et Metabase.
    
        
    docker compose up -d
    
      
    
    
    2. 
    
  2. 
      
      
    
        
    Entrer dans la boîte MinIO
    
        
    Toujours dans le terminal. L'invite change et affiche sh-5.3# : tu es « dedans ».
    
        
    docker exec -it minio sh
    
      
    
    
    3. 
    
  3. 
      
      
    
        
    Créer le bucket et l'ouvrir en écriture
    
        
    À taper dans la boîte MinIO, une seule fois. Si l'alias mon-minio n'existe pas encore, crée-le d'abord (première ligne).
    
        
    mc alias set mon-minio http://127.0.0.1:9000 minioadmin minioadmin123
mc mb --ignore-existing mon-minio/datalake-citybikes
mc anonymous set public mon-minio/datalake-citybikes
exit
    
        
    « public » veut dire que n'importe qui peut lire et écrire dans ce bucket sans mot de passe. C'est ce qui permet au script de marcher sans identifiants. C'est OK sur ton PC pour le projet, mais jamais sur un vrai serveur.
    
      
    
    
    4. 
    
  4. 
      
      
    
        
    Lancer le collecteur
    
        
    De retour dans le terminal normal, dossier datalake-iot. Laisse la fenêtre ouverte, et fais Ctrl+C pour arrêter.
    
        
    python partie-2/citybikes-collector.py
    
        
    Pour vérifier : ouvre localhost:9001 (identifiant minioadmin, mot de passe minioadmin123) et va dans le bucket datalake-citybikes.
    
      
    
    
    5. 
  

  

    Ça affiche « ÉCHEC » pour toutes les villes ?
    
Presque toujours, c'est que l'étape 3 n'a pas été faite : le bucket n'existe pas ou n'est pas public. Si c'est une seule ville qui échoue, c'est sûrement l'API qui a eu un raté : le script réessaiera tout seul au passage suivant.

  






  

    Glossaire
    
Les mots qu'on croise

  

  

    
API
Une porte d'entrée vers un service, pensée pour les programmes. On envoie une requête à une adresse web, on reçoit des données en retour.

    
JSON
Un format de texte pour ranger des données structurées, avec des accolades et des paires « nom : valeur ». Facile à lire pour un programme.

    
CSV
Un tableau sous forme de texte : une ligne par station, les colonnes séparées par des virgules. S'ouvre dans Excel.

    
Bucket
Un grand dossier dans MinIO (ou dans Amazon S3). On en a un par source : datalake-noaa pour la météo, datalake-citybikes pour les vélos.

    
S3
Le service de stockage de fichiers d'Amazon. MinIO « parle la même langue » que S3, ce qui fait que les mêmes outils marchent avec les deux.

    
Data Lake
Un endroit où on stocke beaucoup de données brutes, telles quelles, pour les analyser plus tard. Ici, c'est MinIO.

    
Conteneur
Une « boîte » Docker qui fait tourner un logiciel isolé du reste de ton ordinateur, avec tout ce qu'il lui faut.

    
Terminal
La fenêtre où on tape des commandes en texte (PowerShell, Git Bash, Terminal sur Mac).

    
Requête PUT
Une demande HTTP qui veut dire « enregistre ce contenu à cette adresse ». C'est ce que fait curl pour déposer un fichier.

    
Boucle infinie
Un bout de code qui se répète sans fin (while True). C'est voulu ici : le collecteur doit tourner jusqu'à ce qu'on l'arrête.
